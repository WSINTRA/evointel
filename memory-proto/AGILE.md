# Memory-Proto API Layer — Work Breakdown

## Design principles

- **High cohesion**: each module does one thing. `nodes.rs` = data. `mutations/` = write path. `queries/` = read path. `vector.rs` = search.
- **Low coupling**: mutations and queries both depend on `types/` + `db.rs`. They don't depend on each other. `vector.rs` is standalone.
- **Hidden complexity**: the caller never sees Cypher, never knows edges are nodes, never constructs parameter bindings, never handles `time` ↔ `chrono` conversion.

## Key lbug API notes

- `Connection::query(&str)` — run Cypher, returns `QueryResult` (iterator of `Vec<Value>`)
- `Connection::prepare(&str)` + `Connection::execute(&mut stmt, Vec<(&str, Value)>)` — parameterized queries with `$name` params
- `Value` enum: `String`, `Double`, `Float`, `Timestamp(time::OffsetDateTime)`, `Array(LogicalType, Vec<Value>)`, `Bool`, `Null(LogicalType)`, `Node(NodeVal)`, etc.
- **Timestamps**: lbug uses `time::OffsetDateTime` (not `chrono`). Keep `chrono` in our structs; add small private conversion helpers in `mutations/` and `queries/`.
- **Embeddings**: `Value::Array(LogicalType::Float, vec![Value::Float(x), ...])` for `FLOAT[518]` columns
- **`build.rs`**: already has `-rdynamic` for extensions
- **Schema DDL must be parameterized by embedding dim** so tests can use small dims (e.g. 3) instead of 518

### Task 1: Node type structs

**What:** Define Rust structs in `nodes.rs` for all 7 entity node types: `Note`, `Entity`, `Time`, `AbstractTime`, `Fact`, `Event`, `Memory`.

**Details:**
- Each struct mirrors the DDL columns 1:1
- Embedding fields are `Option<Vec<f32>>` (None until computed)
- Timestamps are `chrono::DateTime<Utc>`
- `Note` is different: has `content` + `content_embedding`, no `label`/`learned_at`/`expire_at`
- `id` is a `String` (UUID, generated by caller)
- Add a `NodeType` enum (`Note`, `Entity`, `Time`, `AbstractTime`, `Fact`, `Event`, `Memory`) with a `label()` method returning the Cypher table name
- No DB dependency — pure data, only uses `chrono` + `serde`

**Files:** `src/nodes.rs`, update `src/lib.rs`

**Tests:** None (pure data). Compilation is the test.

**Depends on:** nothing

### Task 3: `insert_note`

**What:** First mutation function. `mutations/notes.rs` with `insert_note(conn, note: &Note) -> DbResult<()>`.

**Details:**
- Uses `MERGE` (idempotent) with parameterized Cypher: `MERGE (n:Note {id: $id}) SET n.content = $content, ...`
- Handles `content_embedding: Option<Vec<f32>>` → `Value::Array` or `Value::Null`
- Handles `chrono` → `time::OffsetDateTime` conversion (small private helper, reused later)
- Creates the `mutations/mod.rs` with re-exports

**Cypher pattern (the one to establish):**
```cypher
MERGE (n:Note {id: $id}) SET
  n.content = $content,
  n.content_embedding = $embedding,
  n.created_at = $created_at,
  n.updated_at = $updated_at,
  n.layer = $layer,
  n.context = $context
```

**Files:** `src/mutations/mod.rs`, `src/mutations/notes.rs`, update `src/lib.rs`

**Tests (`tests/mutations.rs`):**
- `insert_note_roundtrip`: insert a note, query it back with raw Cypher, verify all fields match
- `insert_note_idempotent`: insert same note twice, verify no duplicate (count == 1)

**Depends on:** Task 1

### Task 6: Edge linking — structural edges (helper + Contains, Similar, HasProperty)

**What:** `mutations/edge_links.rs`. This is the **key complexity-hider**. Introduces:

1. **`NodeRef`** struct: `{ id: String, label: String }` — a typed reference to a graph node (the label is the Cypher table name like `"Note"`, `"Entity"`). This is what lets the Cypher do `MATCH (a:Note {id: $id})`.

2. **Private helper** `create_edge_link(conn, edge_label, from_rel, to_rel, from: &NodeRef, to: &NodeRef, set_clauses, params) -> DbResult<String>`:
   - Step 1: `MERGE (e:EdgeLabel {id: $id}) SET ...`
   - Step 2: `MATCH (a:FromLabel {id: $from_id}), (e:EdgeLabel {id: $id}) MERGE (a)-[:FromRel {role: 'source'}]->(e)`
   - Step 3: `MATCH (e:EdgeLabel {id: $id}), (b:ToLabel {id: $to_id}) MERGE (e)-[:ToRel {role: 'target'}]->(b)`
   - Returns the edge node id

3. **Public functions** (one per edge type):
   - `link_contains(conn, from: &NodeRef, to: &NodeRef, props: &Contains) -> DbResult<String>`
   - `link_similar(conn, from: &NodeRef, to: &NodeRef, props: &Similar) -> DbResult<String>`
   - `link_has_property(conn, from: &NodeRef, to: &NodeRef, props: &HasProperty) -> DbResult<String>`

**Files:** `src/mutations/edge_links.rs`, update `src/mutations/mod.rs`

**Tests:**
- `link_contains_creates_edge_node_and_rels`: insert Note + Entity, link them, verify: (a) Contains node exists with correct props, (b) FROM_Contains rel exists, (c) TO_Contains rel exists
- `link_similar_roundtrip`: same pattern for Similar
- `link_contains_idempotent`: link twice with same id, verify only one edge node

**Depends on:** Tasks 2, 3 (needs edge structs + NodeRef pattern from note insert)

### Task 12: Traversal + temporal queries

**What:** `queries/traversal.rs` + `queries/temporal.rs`.

**Functions:**
- `neighbors(conn, node: &NodeRef, depth: usize) -> DbResult<Vec<(NodeVal, Vec<String>)>>` — BFS up to `depth` hops via all edge-node rels. Returns (node, path_of_edge_labels).
- `connected_notes(conn, entity_id: &str) -> DbResult<Vec<Note>>` — "which notes does this entity connect to?" Follows: Entity ←edge_node← Note (via FROM_X rels) or Entity →edge_node→ Note
- `events_in_range(conn, start: DateTime<Utc>, end: DateTime<Utc>) -> DbResult<Vec<Event>>` — `MATCH (e:Event) WHERE e.learned_at >= $start AND e.learned_at <= $end RETURN e`

**Files:** `src/queries/traversal.rs`, `src/queries/temporal.rs`, update `src/queries/mod.rs`

**Tests:**
- `neighbors_depth_1`: create A -[Similar]-> B -[Contains]-> C, neighbors(A, 1) returns B, neighbors(A, 2) returns B and C
- `connected_notes_finds_source`: insert Note + Entity + Contains edge, connected_notes(entity_id) returns the note
- `events_in_range_filters_correctly`: insert 3 events with different `learned_at`, query a range that matches 2, verify

**Depends on:** Tasks 6-8 (need edges to traverse), Task 11

### Task 13: Full integration eval

**What:** `tests/full_eval.rs` — an end-to-end scenario that proves the memory layer works as a system.

**Scenario:**
1. Open a temp DB (dim=3 for test embeddings), init schema, load extensions, init vector indexes
2. Insert 3 notes (with content embeddings)
3. Insert 2 entities extracted from the notes (with label embeddings)
4. Insert 1 fact, 1 event, 1 memory
5. Insert 1 Time node + wire hierarchy
6. Create edges: Note—Contains→Entity, Entity—Similar→Entity, Fact—LeadsTo→Event, Time—ValidFrom→Fact
7. **Traverse:** `connected_notes(entity_1)` → verify it returns the right notes
8. **Vector search:** search for entity_1's embedding → verify entity_1 ranks first
9. **Temporal:** `events_in_range(week_range)` → verify the event is found
10. **Rebuildability:** record all node counts + edge counts, open a *second* temp DB, replay steps 2-6, verify identical counts

**Files:** `tests/full_eval.rs`

**Depends on:** Tasks 3-12 (all of them)

## Resolved decisions

| Question | Decision |
|----------|----------|
| `chrono` vs `time` | Keep `chrono` in structs; private conversion helpers where lbug needs `time::OffsetDateTime` |
| Embedding dim in tests | Parameterize schema DDL by dim so tests can use small dims (3) |
| `emotions STRING[]` | Use `Value::Array(LogicalType::String, ...)`; smoke test in Task 4 |
