Wunicorm · Version 2 · Design Overview

Wunicorm v2

A notes and planner that uses evolving intelligence to augment daily life and work.

v1 is a self-running engine that evolves a bot's identity from its own reflections.

v2 points that same engine at you: your notes become the input, the model being built is a model of your life, and the output is augmentation — not a chat, not a self-portrait.

The engine stays. The subject of the engine changes.

02 North star

What we keep — the durable core

v1 earned trust through a set of properties that are about how it runs, not what it talks about. v2 re-homes all of them inside the daemon. None of them are replaced.

The task engine

A task is a declared unit of work → an artifact it must produce → a shelf check that proves it actually ran.

Two kinds of truth

Declaration (what should happen) stays separate from observation (what did).

Guards in code, not in a prompt

The shelf check, freshness, outbound gate, fault ledger and redaction are enforced by code, never requested of the model.

Two channels, deliberately split

The reflective letter (about itself) and the mechanical attention card (only when a human is needed).

Encrypted at rest

Memories, reflections — and now everything — sit under a user-held key.

The Jungian framework, as a lens

Shadow, tensions, archetypes, the six rules — repurposed to read you, not discarded.

03 The shape

A local-first daemon, a web UI, a tray icon

In the Jellyfin sense: it runs on your Mac, serves a web app on localhost, and is a resident process — not a script that fires and exits. Exposed to your own devices over Tailscale; never to the public internet.

Tailscale → the same local app, reachable from your other devices on a private mesh — access, not a third party processing your data.
  • The Mac app is a thin shell over the localhost web UI; the note-taking UX is built as a web app for fast iteration.
  • Config lives in the app, not in files you edit by hand.
  • The daemon is the app's heart: it owns the schedule and runs the intelligence in the background.

05 Security & privacy

First-class — the key lives with you

The password is not a login the server checks. It is a key-derivation input: it unlocks a key that is derived in your browser, and the server never sees it. This inverts v1, where the decryption password was a server secret in .env.

01 · first run

Set a password

You choose a master password. The app derives a recovery seed phrase you store somewhere safe — a wallet, a password manager, paper.

02 · later runs

Password unlocks

The password re-derives the key on-device and decrypts existing content. Forget it, and the seed re-derives the key.

03 · at rest

Everything encrypted

Notes, memories, reflections and the graph all sit under the same key — AES-GCM — as ciphertext. No server master key.

04 · at the model

Redaction first

Whatever is handed to an LLM is scrubbed before it leaves the machine — and you can see exactly what was hidden.

Client-side, zero-knowledge. The key is derived on your device (password → KDF → key). Note content is fetched, decrypted and rendered in the browser — the shell is server-rendered, the content is not. "Wrong password" is detected client-side, not by a server 401.
The price, stated plainly. Key management is yours, exactly like a crypto wallet. That is the cost of "privacy is first class" — so the key UX has to be right: the seed shown once, no silent re-derivation, a way to rotate.

07 The knowledge graph

Semantic space-time, held by four pillars

The graph is not a keyword index. Each concept sits at a point in a combined space — what it means (semantic proximity) and when (time). Edges are typed by four pillars. Because time is a dimension of position, a thought can be seen drifting across its neighborhood — which is how it infers habits and thinking.

The processing layer (an LLM) is what reads the notes and makes these judgments — deciding the nodes, the pillar-edges, and where each sits in semantic space-time. Deeper concepts on the space-time model to follow; this is the v1 representation.

10 The durable core, re-homed

Safe because its acting is fenced

v2 is agentic — it proposes and runs tasks, sends, generates. The trust does not come from it being unable to act; it comes from its acting being fenced by code. The v1 guard library moves inside the daemon and keeps its job unchanged.

GuardWhat it enforces
Shelf checka task is a failure unless its artifact exists, is non-empty, was written by this run, and passes its assertions — a green exit code never stands in for a result
Two kinds of truthdeclaration (what should happen) is stored apart from observation (what did)
Outbound gatenothing is sent to a recipient not on the allowlist; no body containing a credential; one send per (task, date)
Fault ledgera known fault is closed by a fix, not by prose, and a fault is not re-described past its budget
Redactioncredential and personal values never reach the log or the model
Two channelsthe letter and the attention card are different channels — the failure of 2026 was one channel carrying the other's news

11 The pipeline's rhythm

Detect is cheap. Process is not.

A continuous sorter watching every keystroke is cheap; running the LLM on every keystroke is not. So the two are split: the sorter detects and queues continuously, and the scheduler triggers processing at intervals. That single split makes "always watching" and "an overnight full run" one coherent flow.

13 What still folds

Open threads for the detail pass

This is a rough plan on purpose. These are the places where the architecture is still soft, and where the detail work happens.

Daemon key access security

How a background daemon decrypts zero-knowledge notes when the app is closed — a secure OS slot (Keychain / Secure Enclave) while the Mac is unlocked, or a defined "unlocked-for-the-daemon" window.

Database choice stack

SQLite for truly single-file local-first, or Postgres to keep the fork. Drizzle covers both; it's a portability call.

The space-time model graph

The deeper concepts behind semantic space-time — how position, embedding and time combine, and how drift is measured. Concepts to come.

"Overnight" = machine-on honest limit

On a local daemon the thorough pass runs when the Mac is awake or idle. An accepted consequence of local-first + Mac-first; stated, not hidden.

The daemon API surface contract

Bearer-token auth + sync endpoints: read notes, write notes, read notes-on-you, tag a CTA, propose / trigger tasks.

How far a task may reach trust

Read-only research vs. something with side effects (a deploy). Confirmation per-task or per-capability, and how the user sets that boundary.

A notes and planner that uses evolving intelligence to augment daily life and work.

A new project from the ground up — but standing on the parts of v1 that earned their place: the task engine, the guards, the two channels, the encrypted memory. The input becomes your notes; the subject of the engine becomes you.
