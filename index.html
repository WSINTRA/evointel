Wunicorm · Version 2 · Design Overview

Wunicorm v2

A notes and planner that uses evolving intelligence to augment daily life and work.

v1 is a self-running engine that evolves a bot's identity from its own reflections.

v2 points that same engine at you: your notes become the input, the model being built is a model of your life, and the output is augmentation — not a chat, not a self-portrait.

The engine stays. The subject of the engine changes.

What we keep — the durable core

v1 earned trust through properties about how it runs. v2 carries them into the daemon. The shelf check, observation reports, and self pass are implemented; agentic task guards remain requirements for the next layer.

Declaration (what should happen) stays separate from observation (what did).

Guards in code, not in a prompt

The shelf check, graph writes, freshness, and self pass are enforced. Task/outbound guards are deferred; redaction is still a stub.

Two channels, deliberately split

Reflective sermon and mechanical notification exist today; a separate attention-card channel is deferred.

The Jungian framework, as a lens

Shadow, tensions, archetypes, the six rules — repurposed to read you, not discarded.

03 The shape

Wunicorm is a local-only, single-user macOS process. You keep writing in Mac Notes; the daemon reads on schedule and returns a sermon through a notification and the Wunicorm Notes folder. There is no web app, localhost server, or Tailscale.

05 Security & privacy

OS-level, local-first, local models by default

Single-user, local-first. Your Mac is the server. The security model relies on the OS, not on an app-level crypto layer.

01 · at rest

FileVault

Full-disk encryption protects the database file. The OS handles screen locks and session security.

02 · local only

No app network layer

No localhost API, Tailscale, or remote app traffic exists. macOS automation permission gates Notes access.

03 · at the model

Local LLMs; redaction pending

The target is local model servers. The redaction seam is currently a stub and must be implemented before any remote endpoint.

No app-level encryption. No client-side zero-knowledge, no password/seed/key-derivation. The daemon owns the data and processes it in plaintext. The threat model is "what if my Mac is stolen" — FileVault covers that.
Revisit if the product grows. If this becomes a distributed or cloud-hosted service, the trust model changes and encryption at the application layer becomes necessary. For a personal, single-user, Mac-first daemon — it is complexity without a matching threat.

07 The knowledge graph

Semantic space-time, held by four pillars

The graph is not a keyword index. Each concept sits at a point in a combined space — what it means (semantic proximity) and when (time). Edges are typed by four pillars. Because time is a dimension of position, a thought can be seen drifting across its neighborhood — which is how it infers habits and thinking.

Leads to — causal
Contains — hierarchical
Near / similar — proximity
Expresses property — attributive

Expresses propertyattributivea concept carrying a value (salary, status, date)

The processing layer (an LLM) reads notes and makes these judgments — deciding nodes, pillar-edges, and each node's position in semantic space-time.

The function space · landed

Two axes

Judgment (thinking ↔ feeling) and perception (sensing ↔ intuiting), built from gate-verified, corpus-mean-centered anchor embeddings.

Two points, one frame

U is the user's note centroid. W comes from Wunicorm's choices: a damped core plus compensation gated by rigidity, never direction.

The self pass

Writes SelfStates and trajectories, grounds claims in evidence, and rebuilds from notes plus the DreamRun choice ledger.

Movement language only

The sermon can say “toward thinking, away from feeling”; numbers are stripped before writing, and no effect is attributed to the system.

13 What still folds

Verification first, then the task layer

The architecture is working; the remaining items are explicit. The most important boundary is that a full live scheduled dream has not yet been accepted.

Live daemon acceptance pending

Prove scheduled ingestion, graph writes, notification, Notes output, quiet-day behavior, and the once-per-day/next-day guard against real Mac Notes and local LLM servers.

Task CTAs and task reach deferred

Design the confirmation surface and separate read-only research from capabilities with side effects. No task engine is exposed yet.

Launch at login deferred

The DMG installs only the app. It does not create a LaunchAgent or start Wunicorm automatically.

Distribution deferred

Developer ID, notarization, and universal Intel/Apple Silicon builds are future work. The current DMG is local and ad-hoc signed.

Remote-model safety required

Implement real redaction before any non-local LLM endpoint. The current redaction seam is a stub.

"Overnight" = machine-on honest limit

The daily pass runs only while the Mac is awake — an accepted consequence of local-first design.

A working Mac Notes daemon with the memory engine intact.

Components, 177 tests, tray appearance, and the DMG are verified. The next milestone is a real scheduled dream; task proposals and broader distribution follow only after that evidence exists.
